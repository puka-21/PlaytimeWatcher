Модульный трекер игрового времени и активности на C#. Программа построена на архитектуре ядро-провайдеры-выводы: ядро отвечает за учет времени, провайдеры парсят логи/сессии конкретных приложений, а выводы отправляют статистику на платформы.

## Архитектура и особенности

* Ядро (`Core`)
  * `TimeTracker` занимается исключительно логикой подсчета времени и ничего не знает о конкретных играх или платформах.
  * Хранение данных (`LocalJsonStatsStore`) полностью изолировано от внешних сервисов и работает локально в `%AppData%\PlaytimeWatcher`.

* Провайдеры (`Providers`)
  * Провайдер Roblox (`RobloxProvider`):
    * Параллельно отслеживает все активные лог-файлы в `%LocalAppData%\Roblox\logs` через `Task.WhenAll`.
    * Корректно разделяет и одновременно считает время для нескольких запущенных окон/аккаунтов.
    * Резолвит `UserId` в реальный никнейм через API Roblox и автоматически подтягивает названия игр.
    * Не использует чувствительные данные (`.ROBLOSECURITY`) — только чтение локальных текстовых логов.
  * Архитектура через интерфейс `IProvider` позволяет легко добавлять отслеживание любых других приложений и игр (Steam и др.).

* Вывод (`Outputs`)
  * **Discord Webhook (`DiscordWebhookOutput`):** Создает и закрепляет ровно одно Embed-сообщение на каждый аккаунт (`<UserId>.msgid`). Обновляет его через `PATCH`-запросы без спама в канал.
  * **Консольный вывод (`ConsoleOutput`):** Пример альтернативного вывода статистики в реальном времени.
  * Полная отказоустойчивость: при недоступности внешних сервисов (например, Discord) ядро продолжает исправно вести локальный учет.

* Защита (`Security`)
  * **Single Instance:** Использование именованного `Mutex` предотвращает повторный запуск нескольких экземпляров программы.
  * **Восстановление данных:** При утере локального JSON-файла статистика может быть восстановлена из сохраненного Discord Embed-сообщения.
